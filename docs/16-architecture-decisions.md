## ADR-001 — Единая форма Create/Edit

**Дата:** 2026-07-30  
**Статус:** Accepted

### Решение

Создание и редактирование упражнения используют один компонент
`ExerciseForm`.

### Причина

- единая валидация;
- отсутствие дублирования;
- одинаковый UX;
- проще поддерживать новые поля.

### Последствия

Страницы `/create` и `/[id]/edit` отвечают за получение данных,
а вся форма находится в общем form-модуле.

## ADR-002 — Разделение Edit loader и mapper

**Дата:** 2026-08-01  
**Статус:** Accepted

### Решение

Загрузка данных Supabase выполняется в `exercise-loader.ts`, а преобразование записи базы данных в состояние формы — в чистом `exercise-mapper.ts`.

### Причина

- UI не зависит от структуры Supabase query;
- mapper можно тестировать отдельно;
- будущие источники данных смогут использовать ту же форму;
- Edit page остаётся компактной.

### Последствия

Storage URL разрешается на уровне страницы, а mapper принимает готовые URL и не импортирует Supabase.

## ADR-003 — Полная синхронизация целей и тегов при Edit

**Дата:** 2026-08-01  
**Статус:** Accepted

### Решение

При сохранении Edit текущие строки `exercise_goals` и `exercise_tags` удаляются и создаются заново из состояния формы.

### Причина

- простой и предсказуемый алгоритм;
- исключение дубликатов;
- небольшое количество связей у одного упражнения;
- отсутствие сложной diff-логики на клиенте.

### Последствия

При ошибке после обновления выполняется best-effort восстановление исходных целей и тегов.

## ADR-004 — Безопасная замена медиа

**Дата:** 2026-08-01  
**Статус:** Accepted

### Решение

Новое медиа сначала загружается в Storage. Старый файл удаляется только после успешного обновления упражнения и связанных данных.

### Причина

Удаление старого файла до завершения сохранения могло бы оставить упражнение без рабочего медиа при ошибке базы данных.

### Последствия

При ошибке новые загруженные файлы удаляются, а старые пути остаются или восстанавливаются.

## ADR-005 — Edit сохраняет текущий статус

**Дата:** 2026-08-01  
**Статус:** Accepted

### Решение

Кнопка `Зберегти зміни` не изменяет статус упражнения. `active`, `draft` и `archived` сохраняются как есть.

### Причина

Редактирование контента и изменение публикационного статуса являются разными действиями.

### Последствия

Публикационный статус изменяется отдельными сценариями, а hero/sidebar Edit отображают фактическое значение из базы данных.

## ADR-006 — Явне видалення медіа через відкладене застосування

**Дата:** 2026-08-01  
**Статус:** Accepted

### Рішення

Видалення обкладинки, схеми або відеофайлу спочатку фіксується у локальному стані форми. Поле media path отримує `null` під час збереження, а фізичний файл видаляється зі Storage лише після успішного update вправи та пов'язаних даних.

### Причина

- користувач може скасувати видалення до збереження;
- помилка бази даних не повинна призводити до втрати чинного файлу;
- заміна і видалення використовують однаковий безпечний порядок операцій.

### Наслідки

Preview і sidebar показують заплановане видалення. Невдале фізичне очищення Storage не блокує збереження даних, але логуються orphan-файли для майбутнього технічного cleanup.

## ADR-007 — Медійне поле показує фактичний стан контенту

**Дата:** 2026-08-01  
**Статус:** Accepted

### Рішення

Для зображень форма показує реальну мініатюру, а для відеофайлу — ім'я та тип контенту. Текстовий стан без preview не використовується, якщо медіа можна ідентифікувати візуально.

### Причина

- тренер одразу розуміє, який файл прикріплено;
- зменшується ризик випадкової заміни або видалення не того медіа;
- поточний і новий файл мають різні, зрозумілі стани;
- дія `Замінити` знаходиться поруч із контентом, до якого вона належить.

### Наслідки

Media-поле приймає preview URL та ім'я persisted-файлу. Новий локальний файл отримує preview до збереження, але фізична заміна у Storage як і раніше відбувається лише після підтвердження форми.

## ADR-008 — Захист форми через стабільний snapshot і navigation guard

**Дата:** 2026-08-01  
**Статус:** Accepted

### Рішення

Початковий стан Exercise Form серіалізується у стабільний snapshot. Поточний snapshot охоплює поля форми, цілі, вікові групи, теги, нові файли та відкладене видалення медіа. Якщо snapshots відрізняються, форма вважається зміненою.

Навігаційний guard захищає:

- `Скасувати`;
- внутрішні посилання Coach Workspace;
- кнопку браузера `Назад`;
- оновлення та закриття вкладки.

### Причина

- один механізм однаково працює для Create та Edit;
- повернення значень до початкового стану автоматично прибирає попередження;
- заміна або видалення медіа враховується так само, як зміна текстового поля;
- успішне збереження виконує контрольований redirect без зайвого попередження.

### Наслідки

Функції збереження повертають `exerciseId`, а навігація після успішної операції виконується на рівні форми через `navigateAfterSave`. Це відокремлює persistence від browser navigation і дозволяє коректно зняти guard.

## ADR-009 — Імпорт використовує стабільний код вправи

**Дата:** 2026-08-01  
**Статус:** Accepted

### Рішення

Поле `code` є обов'язковим для імпорту та використовується для пошуку дублікатів. Користувач обирає глобальну стратегію: пропустити існуючі записи або оновити їх текстові дані, класифікацію, цілі та теги.

### Причина

- назва вправи може змінюватися і не є стабільним ключем;
- код дозволяє повторно імпортувати версії одного контент-пака;
- майбутній Marketplace та обмін бібліотеками потребують переносимого ідентифікатора.

### Наслідки

Коди у файлі нормалізуються до uppercase і перевіряються на дублікати всередині самого файлу. Update-імпорт не змінює медіафайли існуючої вправи.

## ADR-010 — Preview і validation перед persistence

**Дата:** 2026-08-01  
**Статус:** Accepted

### Рішення

JSON/CSV спочатку парситься, нормалізується та показується у preview. У базу передаються лише рядки без validation errors.

### Причина

- тренер бачить проблеми до зміни бібліотеки;
- одна некоректна вправа не блокує валідні записи;
- import report зберігає прозорість масової операції.

### Наслідки

Parser, validator і persistence service є окремими модулями та можуть бути протестовані незалежно.
