# Sprint 3 — Exercise Create/Edit Workspace

## Цель

Подготовить единый переиспользуемый интерфейс создания и редактирования упражнения без дублирования разметки, состояния формы и логики сохранения.

## Текущее состояние

### Завершено

- Создан единый `ExerciseForm` с режимами `create` и `edit`.
- Состояние, валидация, загрузка медиа и сохранение находятся в `useExerciseForm`.
- Справочники формы вынесены в `config/exercise-options.ts`.
- Типы формы вынесены в `types/exercise-form.ts`.
- Созданы отдельные компоненты hero, actions и sidebar.
- Создан общий модуль `components/workspace`.
- Create-страница использует общий workspace shell и двухколоночный layout.
- `/admin/coach/exercises/new` перенаправляет на `/create`.
- Реализована загрузка упражнения, целей и тегов по ID.
- Реализовано преобразование Supabase record в `ExerciseFormInitialData`.
- `/admin/coach/exercises/[id]/edit` использует общий `ExerciseForm`.
- Реализовано обновление основных полей упражнения.
- Реализована синхронизация `exercise_goals` и `exercise_tags`.
- Реализована безопасная замена обложки, схемы и видео.
- Старые файлы удаляются только после успешного сохранения новых данных.
- При ошибке выполняется best-effort rollback данных, связей и новых файлов.
- Статус существующего упражнения сохраняется при редактировании.
- Hero и sidebar показывают фактический статус: `draft`, `active` или `archived`.
- Отмена на Edit возвращает на Details текущего упражнения.

### Следующий шаг

- Добавить защиту от потери несохранённых изменений.

- Провести финальный responsive и accessibility QA.

## Save flow

### Create

```text
validate
→ authenticate
→ insert exercise
→ upload selected media
→ update media paths
→ replace goals
→ replace tags
→ redirect to Details
```

### Edit

```text
validate
→ authenticate
→ upload replacement media
→ update exercise and media paths
→ replace goals
→ replace tags
→ delete replaced old media
→ redirect to Details
```

При ошибке Edit выполняется попытка восстановить предыдущие поля, цели, теги и удалить новые загруженные файлы.

### Read flow

- Название, категория, тип, формат, сложность, длительность и игроки заполнены.

- Фактический статус упражнения отображается в hero и sidebar.

### Save flow

- Изменение названия сохраняется и отображается на Details.
- Изменение категории, типа, формата и сложности сохраняется.
- Изменение длительности и количества игроков сохраняется.
- Добавление и удаление целей синхронизируется с `exercise_goals`.
- Первая выбранная цель сохраняется в `primary_goal`.
- Добавление и удаление тегов синхронизируется с `exercise_tags`.
- Возрастные группы сохраняются.
- Новая обложка заменяет старую.
- Новая схема заменяет старую.
- Новый видеофайл заменяет старый.
- Если медиа не меняли, существующие пути сохраняются.
- Активное упражнение остаётся активным после Edit.
- Черновик остаётся черновиком после Edit.
- Архивное упражнение остаётся архивным после Edit.
- После успешного сохранения выполняется переход на Details.

## Sprint 3.6.0 — Керування медіа вправи

### Додано

- Явні дії `Замінити файл` і `Видалити` для обкладинки, схеми та відеофайлу.
- Стан `Буде видалено після збереження` з можливістю скасувати видалення.
- Очищення зовнішнього відеопосилання окремою дією.
- Preview та sidebar одразу відображають заплановане видалення або новий вибраний файл.

### Безпечне збереження

```text
позначити медіа для видалення
→ зберегти вправу з null у відповідному media path
→ синхронізувати цілі та теги
→ видалити старий файл зі Storage
→ перейти на Details
```

Старий файл не видаляється зі Storage до успішного оновлення вправи. Якщо користувач не змінював конкретне медіа, його шлях залишається без змін.

### QA checklist

- Видалити існуючу обкладинку та зберегти — обкладинка зникає з Details і Library.
- Скасувати видалення обкладинки — початкове preview відновлюється.
- Замінити обкладинку — нова зберігається, стара видаляється після успішного update.
- Повторити сценарії для схеми та відеофайлу.
- Очистити зовнішнє відеопосилання та зберегти.
- Не змінювати медіа та зберегти інші поля — усі media paths залишаються без змін.
- При помилці збереження нові завантажені файли очищаються, а попередні дані відновлюються best-effort rollback.

## Sprint 3.6.2 — Unsaved Changes Protection

### Реалізовано

- стабільний dirty-state для текстових полів, select-полів, цілей, вікових груп і тегів;
- нові, замінені та позначені для видалення медіафайли входять до dirty-state;
- `Скасувати` запитує підтвердження лише за наявності незбережених змін;
- внутрішні посилання на сторінці форми захищені від випадкового переходу;
- кнопка браузера `Назад` захищена history guard;
- оновлення або закриття вкладки використовує стандартний browser warning;
- після успішного Create/Edit redirect виконується без попередження;
- якщо користувач повернув усі значення до початкових, форма знову вважається чистою.

### QA checklist

- Відкрити Edit без змін і натиснути `Скасувати` — перехід без попередження.
- Змінити назву та натиснути `Скасувати` — з'являється підтвердження.
- Відхилити підтвердження — користувач залишається у формі, дані не втрачаються.
- Підтвердити — виконується перехід на Details.
- Змінити поле та натиснути посилання `До бібліотеки вправ` або пункт sidebar — з'являється підтвердження.
- Змінити поле та натиснути browser Back — з'являється підтвердження.
- Змінити поле та оновити/закрити вкладку — браузер показує системне попередження.
- Змінити поле, потім повернути початкове значення — попередження більше не з'являється.
- Вибрати нову обкладинку, схему або відео — форма стає dirty.
- Позначити persisted-медіа для видалення — форма стає dirty; скасувати видалення — стан відновлюється.
- Успішно зберегти Create/Edit — redirect на Details без повторного попередження.
