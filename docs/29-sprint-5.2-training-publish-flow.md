# Sprint 05.2 — Training Publish Flow

## Цель

Добавить жизненный цикл Training Plan и связать методический план с конкретной
training-записью, которую используют страница команды, Push и Attendance.

## Жизненный цикл

```text
Чернетка → Заплановано → Опубліковано → Завершено
                         └────────────→ Скасовано
Скасовано → Заплановано / Опубліковано
Опубліковано → Заплановано через «Зняти з публікації»
```

## Итоговая модель после Sprint 05.2.1

- Черновик не создаёт тренировку.
- «Запланувати» создаёт одну неактивную training-запись на выбранный день.
- «Опублікувати» активирует эту же запись для игроков.
- Повторная публикация выполняет update, а не создаёт дубликат.
- Attendance всегда использует тот же `training_id`.
- Push-уведомления уже работают и вызываются для публикации, переноса,
  изменения места/команды, отмены и восстановления активного события.
- Общий клубный календарь не входит в Sprint 05.2.

## Разделение ответственности

### Training Plan

Содержит цель, интенсивность, упражнения, порядок, длительность блоков,
собственные блоки и внутренние заметки тренера.

### Training

Содержит дату, время, место, команду, статус, player-facing active state и
посещаемость.

## Основные поля

В `training_plans` используются:

- `training_id`;
- `session_date` / `session_time`;
- `location` / `team_name`;
- `published_at` / `published_by`;
- `unpublished_at`;
- `cancelled_at` / `cancellation_reason`;
- `status_before_cancel`.

В `trainings` Sprint 05.2.1 добавляет:

- `team_name`;
- `was_active_before_cancel`.
